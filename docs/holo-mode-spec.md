## 0. 目標與範圍

**目標**：在網頁模式、OS 模式之外，加上**第三種體驗模式「全像模式」（程式代號 `holo`）**。七個功能畫面不再是 2D 網頁，而是一個個可以伸手進去的 3D 資料空間：拖曳旋轉、滾輪縮放、把資料「抓起來」，在面前展開成一塊終端機面板來閱讀和編輯。

**定位**：與 OS 模式相同，是給使用者自己與展示用的炫技模式。現場日常記錄仍以網頁模式為主；OS 2D 工作站是全像模式的後備。

**範圍內**
- 全像模式外殼、七個頻道的全像場景、終端板（所有閱讀與輸入）、儀器環、文字分身。
- 三段後備：全像 → OS 2D → 網頁。
- **OS 模式控制室的 HUD 重新設計**，尤其是下排頻道列（H0）。
- 為了讓業務邏輯只存在一份，把頁面元件裡的邏輯抽成共用 hook（零行為變更，H2）。
- 網頁模式 Combobox／CopyPicker 選字時按 Enter 的缺陷修正（獨立小 PR，§12.1）。

**範圍外（明確不做）**
- 後端、API、資料格式的任何改動。
- 任何新的業務功能，例如照片排序、自動存檔、新的欄位或新的統計口徑。
- 手勢、攝影機、MediaPipe。
- 手機與平板（寬度 < 1280px 不提供全像模式，見 §8）。
- 網頁模式的任何視覺或行為改變。§12.1 的 IME 修正是唯一例外，屬於修 bug。

### 0.1 名詞

| 名詞 | 意思 |
|---|---|
| 全像模式 | 本文件描述的模式。程式代號 `holo`，`<html data-mode="holo">` |
| 全像外殼（HoloShell） | 全像模式下取代 `AppShell`／`OsShell` 的外殼 |
| 世界（World） | 一個頻道的 3D 全像場景，在中景 |
| 終端板（Slate） | 浮在世界前方的真 DOM 面板，用來閱讀與輸入，A 層 |
| 儀器環（Instrument Ring） | 圍在畫面邊緣、不隨世界轉動的監看與控制面板，C 層 |
| 文字分身（Text Twin） | 世界裡全部物件的等價文字清單；螢幕閱讀器與純鍵盤操作以它為主 |
| 物件（Object） | 世界裡可以被選取、抓起的東西：一筆紀錄卡、一台機台、一天、一棟長條 |
| 抓起／放下 | 打開或關閉某個物件的終端板。紀錄卡的「抓起」就是 `?open=<id>` |
| 釘選 | 把物件的監看讀數固定到儀器環上（只是呈現狀態，存在本機） |
| 後備階梯 | 全像 → OS 2D → 網頁，任何一層失敗就降到下一層 |

### 1.4 盤點的關鍵結論（決定本規格做法的事實）

1. 資料層乾淨可直接重用：
   - `useRecords()` 一次抓回全部紀錄；篩選、排序、彙總都是 `@shared/aggregate` 的純函式。
   - 表單是 `form/model.ts`（純函式）加 `formReducer.ts`。
   - 照片上傳狀態機是 `usePhotoUploads`。
2. 邏輯綁在元件上的部分：
   - `RecordForm`（644 行）把送出、離開確認、焦點、`?copy=` 同步都寫在元件裡。
   - 詳情面板的 `?open=` 歷史協議和焦點回復也綁在元件上。
   - 這些要先抽成 controller hook（H2）。
3. 沒有分頁、沒有虛擬化；照片是原圖，最大 25MB，伺服器不產生縮圖。
4. 真實資料規模（2026-11-08 唯讀統計）：
   - 156 筆、每月約 90 筆、15 台設備、22 種分類。
   - 照片 300 張，中位數約 240KB。
   - 處理狀態目前全部是「已解決」。
   - **設計負載訂為 5,000 筆（正常）、20,000 筆（壓力上限）。**
5. 網頁元件原本沒有 `isComposing` 保護：Combobox 的 Enter 一律 `preventDefault`，有反白的建議才選取、否則收起清單；CopyPicker 在清單開著時 Enter 會帶入反白那筆。選字中的 Enter 因此會誤選（已由 §12.1 修正）。OS 的 `escapeRule.ts`、`keymap.ts` 已有保護。
6. OS 頻道列突兀的六個原因見 §7.1。

## 2. 不可破壞的紅線

1. **網頁模式零差異**：標準與 Cyber 主題的畫面、行為、測試結果與導入前相同（S1）。唯一例外是 §12.1 的 IME 修正，有獨立 PR 與測試。
2. **業務邏輯只存在一份**（H-U6，取代 OS 規格的「不改頁面元件」）：
   - 允許把邏輯從頁面元件抽成共用 hook 或純函式，但**不能改行為**：網頁模式與 OS 2D 的 C1 零差異，既有測試不改也要通過。
   - 全像的呈現層另外新寫，**禁止複製業務邏輯**（驗證、彙總、送出流程、toast 文案、導覽路徑）。
   - 前端驗證只能有 `form/model.ts` 一份。
3. **功能零差異**：全像模式裡每個功能的資料、驗證、文字、流程都和網頁模式相同。附錄 A 的行為清單逐條驗收。
4. **操作絕不被擋**（FX-02 教訓）：
   - 轉場、鏡頭飛行、抓起動畫在交接點之前的輸入都直接跳到終點，交接點之後立刻可以操作。
   - 禁止使用 View Transitions。
   - 疊層一律 `pointer-events: none`。
   - 拖曳手勢有明確的結束條件（§5.4）。
5. **不繞過 `useBlocker`**：任何離開（Esc、回控制室、指令列、上一頁、切模式、後備降級）都要先經過路由導覽，讓既有的離開確認攔得到。
6. **列印與報表不變**：列印時隱藏全部全像元素；報表一律交給現有的 `#report-output` 列印與開新視窗，結果與網頁版相同（E4）。
7. **沿用 Cyber 紅線**：對比、嚴重度用色、狀態用形狀、焦點、字型自行託管、toast 一律走 `lib/feedback.ts`、不寫死色碼。
8. **無障礙**：世界只是裝飾（`aria-hidden`）；每個物件操作都有文字分身與鍵盤路徑；所有輸入都是真的 `input`、`textarea`、`select`。
9. **`prefers-reduced-motion`**：不飛鏡頭、世界靜止、抓起直接出現終端板（§5.7）。
10. **套件精確版本鎖定**：沿用 three 0.186.1、@react-three/fiber 8.18.0；新增套件要先問設計師（§3.6）。
11. **資料安全**：開發與驗證不准讀寫真實資料夾，也不准把它當 `DATA_DIR`；一律用範例資料副本或 §11.2 的合成資料，port 用 3114–3116，並設 `NO_OPEN_BROWSER=1`。
12. **整個模式延遲載入**：網頁入口 gzip 增加 ≤ 2KB；全像程式只經動態 `import()` 載入，每個頻道各自一個 chunk（§10.2）。

## 3. 架構

### 3.1 模式與後備階梯

```
 web（AppShell） ⇄ os（OsShell：控制室＋2D 工作站） ⇄ holo（HoloShell：控制室＋全像世界）
                           ▲                                   │
                           └──── 後備：WebGL2 失敗／裝置門檻／載入失敗 ────┘
```

- `lib/mode.ts` 的 `Mode` 型別擴充為 `"web" | "os" | "holo"`。`?mode=holo` 覆寫並寫回；`index.html` 首繪前的 inline script 同步擴充（`mode.test.ts`、`theme.test.ts` 會比對）。
- **後備是降一級**：
  - 全像失敗時，這次載入改用 `os`，畫面顯示一行「全像模式無法啟動，已改用 OS 模式」，不寫回 `pld.mode`。
  - OS 也失敗時沿用現行規則，回到網頁模式。
- 模式切換先做一次路由導覽，通過 `useBlocker` 之後才換外殼；上一頁、下一頁（POP）永遠不切換模式（沿用 OS 規則）。
- `HoloShell` 掛載時設 `data-mode="holo"`，並呼叫 `applyTheme("cyber")`（只為了取得 Cyber 色票與字型；只套用、不寫入偏好）；卸載時依 `pld.theme` 還原。
- **Cyber 特效屬性**：全像自己的呈現元件（世界、終端板、儀器環、文字分身）**不輸出任何 `data-fx` 屬性**，也不使用 `useFx()` 的動畫。終端板裡共用的既有元件（Combobox、ConfirmDialog、Lightbox、toast）保持原樣，照 Cyber 外觀顯示。HS3 以「`.holo-slate` 內除了上述共用元件，沒有 `data-fx`」檢查。
- **切換模式只在控制室進行**：狀態列的 `OS｜HOLO` 切換鈕只在 `/os` 顯示。在頻道裡用指令 `os`／`holo` 時，先導向 `/os`（路由先行，經過 blocker；取消就不切換），抵達後才換外殼。`/os` 幽靈歷史紀錄的跳過規則（`ModeShell` 的 `ghostStep`）同樣適用全像模式。

### 3.2 路由

**路由與網頁模式共用，不新增路由。**
- 控制室：`/os`，OS 與全像共用（H-D2）。
- 頻道對應沿用 `features/os/channels.ts`，是唯一的對照來源。CH-02 涵蓋 `/records` 與 `/records/:id/edit`，CH-03 是 `/records/new`。
- **抓起紀錄卡＝`?open=<id>`**。push、replace、detailPush 的規則和詳情面板完全相同；這個協議由 H2 抽出的 `useOpenRecordParam()` 管理。
- **編輯＝`/records/:id/edit`**，同頻道內不播轉場；存檔後 replace 回 `/records?open=<id>`。
- **新增**存檔後照網頁版導向 `/dashboard`，跨頻道時播飛行轉場；toast「查看」連到 `/records?open=<新id>`。
- 下鑽一律走 `lib/drill.ts`：先清條件，再帶單一值到 `/records`。

### 3.3 三層畫面（駕駛艙）

```
┌──────────── 儀器環（C，固定於畫面，真 DOM）──────────────┐
│ ┌──────┐                                         ┌──────┐ │
│ │篩選／│        世界（B，WebGL，可轉可縮）        │ 監看 │ │
│ │參數  │   ◇ ◇ ◇ 物件 ◇ ◇ ◇      ┌──────────┐     │ 釘選 │ │
│ │      │                          │ 終端板 A │     │ log  │ │
│ └──────┘                          │（真 DOM）│     └──────┘ │
│  狀態列（頻道、模式、SND、CRT、EXIT）└──────────┘             │
└───────────────────────────────────────────────────────────┘
```

| 層 | 技術 | 責任 | 規則 |
|---|---|---|---|
| 世界 B | r3f 畫布，`aria-hidden` | 視覺化、空間探索、選取與抓起的對象 | 不畫任何文字（文字交給讀數標籤與終端板）；`pointer-events` 只接受世界本身的拖曳、點擊 |
| 終端板 A | 真 DOM，`position: fixed`，用世界座標投影定位 | 閱讀詳情、所有輸入、文字分身 | 內容區清晰：不疊掃描線、光暈、半透明；全像效果只能在板框上（取代 OS 的「C 區清晰」） |
| 儀器環 C | 真 DOM，貼齊畫面邊緣 | 篩選與參數、監看讀數、釘選、警報、狀態列 | 不隨世界轉動；線框與切角語彙，與 H0 的 OS HUD 同一套設計 |
| 讀數標籤 | 真 DOM，投影定位 | 懸停或選中時浮出一行讀數，例如 `M-07 ▸ 嚴重 2｜重大 1` | 同時最多 24 個；`aria-hidden`，資訊在文字分身裡都有 |

- **不使用 CSS 3D**：OS 的 `.os-root` 禁止 transform 和 filter，全像也照這條守。終端板與標籤一律在每幀用 `Vector3.project()` 算出畫面座標，再設定 `transform: translate()`。這個 translate 只加在終端板自己身上，不加在根節點。H1 會再驗證這個做法。
- 終端板**最多一塊主板加兩塊釘選小板**。主板寬 480–720px（依內容），高度不超過畫面高度的 80%，超出捲動；投影位置會被夾在畫面內，最少留 24px 邊距。

### 3.4 共用核心（H2 抽出，零行為變更）

| 共用件 | 來源 | 使用者 |

| `isRecurringProblem(records, r)` | `RecordDetailSheet.tsx` 內聯判斷 | 同上 |

## 4. 視覺語言

### 4.1 三層混合原則

| 來源 | 角色 | 一句話 |
|---|---|---|
| B 資料手套 | 世界 | 資料是可以伸手進去轉、縮、抓的立體物件 |
| A 磷光終端機 | 語言 | 所有文字與輸入都是終端機：等寬、製表框線、游標、`▸` 提示 |
| C 戰情室 | 儀器 | 畫面邊緣是固定的儀表、示波器、log 與警報，給人方向感 |

參考：
- 《攻殼機動隊》（1995）的線框全像
- 《捍衛機密》（1995）的資料手套
- 《駭客》（1995）的 3D 檔案城市
- 《侏羅紀公園》（1993）的 3D 檔案瀏覽器
- 《新世紀福音戰士》（1995）NERV 作戰室的警報字體
- 1969 年 NASA 任務控制中心

只取氣氛與語彙，不重製任何作品的畫面、角色或標誌。

### 4.2 全像材質

- **線條**：
  - 只有線，沒有實心面；物件的「面」最多是 6% 不透明度的 accent 薄膜，讓前後關係看得出來。
  - 線寬 1.5px（DPR 1）；選中時 2.5px，加外光暈。
- **景深霧**：離鏡頭越遠越淡。最遠的物件保留 15% 亮度，不完全消失。
- **光暈**：加色混合。標準強度是單次模糊、半徑 4px；濃是 8px。關閉時沒有光暈。
- **掃描線**：只疊在世界上，2px 週期、5% 強度，終端板與儀器環上不疊。
- **閃爍**：每 6–12 秒（隨機）整個世界亮度掉 8%、持續 60ms。減少動態效果或 CRT「關」時不閃。
- **磷光殘影**：全像模式預設關閉，因為物件持續移動時殘影太長（OS D8 的教訓）。
- **嚴重度**：用色，沿用 Cyber 嚴重度 token；不靠色彩辨識的人，在讀數標籤與文字分身裡一定有文字。
- **狀態**：用形狀與亮度。
  - 已解決：亮度 55%、線條不加光暈。
  - 待處理：實線框，加一個角標。
  - 追蹤中：外框虛線並緩慢流動（減少動態效果時靜止）。
  - 狀態只有三種：待處理、追蹤中、已解決（`STATUS_ORDER`）。

### 4.3 終端板

- **外框**：
  - 切角框線（右上與左下各切 12px），和 H0 的 OS HUD 是同一套語彙。
  - 標題列格式 `CH-02 ▸ REC #63 ▸ 2026-11-07 14:20`。
  - 右上角有 `[ESC] 放下` 提示。
- **內容區**：
  - 背景用 `--surface` 不透明，文字對比 ≥ 4.5:1。
  - 不加掃描線、光暈或模糊（取代 OS 的「C 區清晰」）。
- **欄位（TUI 風格）**：
  - 標籤靠左、等寬，例如 `問題▸`；輸入框是真的 `<input>`／`<textarea>`。
  - 焦點環沿用 Cyber，錯誤訊息以 `role=alert` 顯示在欄位下方。
  - Combobox 的行為和現有元件完全相同（附錄 A 第 31 條）。
- **出現與收合**：
  - 抓起時，板框從物件的投影位置展開，150ms 時文字可讀、可操作（交接點），300ms 時動畫結束。
  - 放下時反向收合，150ms 內完成。

### 4.4 儀器環

- 上方是狀態列：頻道名、模式切換 `OS｜HOLO`、`SND`、CRT 強度、`EXIT`、時鐘。高 40px，透明底，只有線與文字。
- 左側欄寬 280px，放篩選與參數，例如 CH-02 的篩選、CH-05 的報表參數。
- 右側欄寬 280px，由上而下是：該頻道的既有區塊（例如 CH-01 的 KPI）、釘選（最多 3 個）、操作紀錄（本分頁的介面事件，例如「已抓起 #147」，只在記憶體，不存檔）。
- 「深層」投放區：開始拖曳物件時，世界畫面底部 15% 高度出現一條投放帶（線框、`aria-hidden`），放開在帶內＝軟刪除；右側釘選槽同時亮起。不拖曳時兩者都不顯示。
- 狀態列另有〔EXPORT〕按鈕，與指令 `export` 都呼叫既有的 `useExportAction`（附錄 A 第 41 條）。
- 下方沒有色帶。頻道切換放在狀態列的頻道名下拉，或用指令列；1–7 數字鍵只在控制室有效（沿用 OS）。
- 1280 寬時兩側欄縮成 48px 的圖示列，點開後以浮層顯示。
- **警報語法**：有新的嚴重或重大異常時，儀器環的框線整圈轉紅，閃 3 次後保持紅框。右側出現 `ALERT ▸ M-07 重大`；世界裡對應的物件同步閃爍。確認方式沿用 OS 的 `alerts.ts`。

### 4.5 讀數標籤

- 一行等寬字，前面接一條 1px 引線指向物件，例如 `F3 ▸ 次數 32` 或 `#147 ▸ 11/04 14:20 ▸ 嚴重 ▸ 已解決`。讀數只用既有欄位與既有統計。
- 懸停顯示；選中後常駐；同時最多 24 個，超過時只顯示最靠近鏡頭的。

## 5. 操作語法

### 5.1 動詞

| 動詞 | 滑鼠 | 鍵盤（世界取得焦點時） | 效果 |
|---|---|---|---|
| 看 | 懸停 | ←→↑↓ 移動選取 | 選中物件並浮出讀數標籤 |
| 轉 | 左鍵拖曳 | Shift+←→↑↓ | 繞目前焦點旋轉世界 |
| 縮放／前進 | 滾輪 | PageUp／PageDown（也接受 `=`、`-` 與數字鍵盤的 `+`、`-`） | 縮放；CH-02 改為沿時間軸前進或後退 |
| 平移 | 右鍵拖曳或 Shift＋左鍵拖曳 | Ctrl+←→↑↓ | 平移視角 |
| 抓起 | 單擊物件（不是拖曳） | Enter | 打開該物件的主終端板 |
| 放下 | 點世界空白處 | Esc | 關閉主終端板，焦點回到物件（或文字分身裡的對應列） |
| 丟 | 把物件拖到右側釘選槽，或拖到下方的「深層」 | 終端板上的〔釘選〕〔刪除〕按鈕 | 釘選，或軟刪除（與詳情的刪除相同：不問確認，有復原 toast） |
| 回正 | 雙擊世界空白處 | `R` | 鏡頭回到該頻道的預設視角 |
| 文字分身 | 狀態列〔TEXT〕按鈕 | `T` | 切換文字分身的可見性 |
| 指令 | — | `/` 或 Ctrl+K | 指令列（沿用 OS 的 commands，新增 `holo`、`os`、`text`、`reset`） |

- 單字元鍵（`T`、`R`、`=`、`-`）**只在世界取得焦點時**有效。世界容器是 `tabindex=0`、`role="application"`，`aria-label` 依頻道組成：「{頻道編號} {頻道名稱}全像空間，方向鍵移動、Enter 打開、T 文字清單」。
- 焦點在終端板或儀器環裡時，這些鍵照一般輸入處理。

### 5.2 選取與焦點

- 世界取得焦點時，一定有一個「目前物件」。←→↑↓ 依該頻道定義的順序移動（例如 CH-02 依時間順序），同時寫進文字分身的 `aria-activedescendant`。
- 抓起後，焦點移到終端板的標題，或第一個可操作的元件；放下後，焦點回到原本的物件。物件已經消失時（例如被刪除），焦點改到時間上相鄰的物件。
- 焦點與宣告的逐幀重試規則沿用 `useModeShell()`（OS D11）。

### 5.3 Esc 規則（一次只做一件事）

依優先順序。第 1、2、5 步沿用 `escapeRule.ts` 的現行判斷；第 3、4 步是新邏輯，要有自己的單元測試，包括「終端板與文字分身同時開著時，只關終端板」：
1. 有浮層（Combobox 清單、確認對話框、燈箱、指令列）時，只關浮層。
2. 焦點在輸入元件裡時，不做事。
3. 有主終端板時，放下。
4. 文字分身開著時，關閉文字分身。
5. 以上都沒有時，離開頻道回控制室：路由先導向 `/os`，再經過 blocker。

### 5.4 拖曳與輸入閘

- 按下後位移 ≥ 4px 才算拖曳；未達 4px 就放開算點擊（抓起）。
- 拖曳期間使用 pointer capture。以下任何一種情況都算手勢結束：`pointerup`、`pointercancel`、`lostpointercapture`、視窗 `blur`、`visibilitychange` 變成 hidden。結束後必定清除拖曳狀態。
- **輸入閘擴充**：轉場交接點之前的 `pointerdown`，連同它後面的整段拖曳與 click 都會被吞掉，並跳到轉場終點。以上述結束條件判定手勢結束，600ms 安全逾時保留。
- 拖曳中如果發生路由導覽（例如資料變動導致目前物件消失），拖曳立刻取消，不產生「丟」。
- 拖曳中切換到減少動態效果時，拖曳照常完成，但鏡頭不做慣性滑動。

### 5.5 鏡頭

- 每個頻道定義一個預設視角，以及縮放範圍和旋轉範圍（避免翻到世界底下迷路）。
- 放開拖曳後，慣性滑動 ≤ 400ms；減少動態效果時沒有慣性。
- 抓起物件時，鏡頭不移動，物件原地亮起，終端板展開；物件會留在畫面上，讓人看得出是從哪裡抓起的。

### 5.6 頻道內與頻道間

- 頻道內（例如 `?open=` 換一筆、進入編輯）：不播轉場，只有終端板的展開與收合。
- 頻道間（例如新增後到 CH-01、下鑽到 CH-02）：H10 之前用 OS 的 300ms 短轉場；H10 之後改為飛行轉場（≤ 600ms，交接點 250ms）。
- 控制室進出：H10 之前沿用 OS 的進入 1200ms 與離開 900ms；H10 之後改成「穿過螢幕」版本（§9.1），長度與交接點不變。

### 5.7 減少動態效果

- 世界靜止：沒有閃爍、慣性、物件漂浮，或追蹤中虛線的流動。
- 抓起與放下：終端板直接出現與消失，沒有展開動畫。
- 鏡頭不飛行：頻道切換與進出直接切換，焦點與宣告規則照舊。
- 拖曳旋轉和滾輪縮放仍然可用，因為這是使用者自己發起的動作；只是沒有慣性。
- 執行中切換到減少動態效果時立即生效（沿用 OS 的 `instant` 規則）。

## 6. 頻道設計

每個頻道都要符合附錄 A 對應的行為清單。下表的「世界」是視覺化，「終端板」是閱讀與輸入，「儀器環」是固定控制。

### 6.1 CH-02 紀錄：時間螺旋（H4、H5）

- **世界**：
  - 一條往遠方延伸的螺旋，軸線是時間，現在在最前面。一圈＝7 天，半徑 6 單位，每圈前進 4 單位。
  - 每筆紀錄是一張卡片（線框矩形）：
    - 位置：日期加時間（本地時間字串比較，不轉 UTC）。
    - 寬度：耗時，有下限，耗時 0 也看得到。
    - 顏色：嚴重度；亮度與外框依狀態（§4.2）。
    - 有照片：卡片右上加一個小相機角標。
  - 同一天的卡片沿徑向往外疊。目前資料單日最多 11 筆。
  - 順序沿用 `chronological(active)`，和詳情的上下筆一致。
- **LOD**：
  - 時間游標前後各 8 週：完整卡片（InstancedMesh）。
  - 8–52 週：小方點。
  - 再往外：每週一條刻度線。
  - 5,000 筆時同時繪製的完整卡片 ≤ 1,500 張。
- **篩選**：
  - 左側儀器欄的篩選器寫回和網頁版相同的 URL 參數（`lib/urlQuery.ts`）。
  - 不符合條件的卡片淡到 15%，不移除，空間位置保持不變。
  - 儀器欄顯示「共 x / y 筆」（`aria-live=polite`）。
- **時間游標**：
  - 滾輪或 PageUp／PageDown 一次移一天，Shift＋滾輪一次移一週。
  - 左側欄有日期跳轉（沿用 `DateRangeFilter` 的規則）。
- **抓起卡片**＝`?open=<id>`，詳情終端板依附錄 A 第 17–23 條：
  - 顯示欄位依原本順序。
  - 快速改狀態、補根本原因。
  - 〔編輯〕〔複製為新紀錄〕〔刪除〕。
  - 上一筆和下一筆：終端板的 ◀ ▶ 按鈕，世界裡的鏡頭同步沿螺旋移動。
  - 照片縮圖點開沿用 `Lightbox`（DOM 浮層）。
- **刪除**：卡片碎成線段往下沉入深層，與 CH-06 的空間相連。復原 toast 和網頁版相同。
- **編輯**（H5）：
  - 〔編輯〕導向 `/records/:id/edit`，詳情終端板原地換成表單終端板，用 `useRecordFormController`。
  - 存檔時：成功卡片才回到螺旋上的位置並亮一下；失敗時錯誤顯示在終端板裡。

### 6.2 CH-03 新增（H5）

- **世界**：

### 6.3 CH-01 儀表板：工廠數位分身（H6）

## 7. OS 模式 HUD 重新設計（H0）

### 7.1 現況問題
1. 下排頻道列是一條不透明的 `--surface` 色帶，蓋住 3D 底部；鏡頭構圖完全沒把它算進去。
2. 按鈕是網頁式的 1px 方框，沒有切角或線框語彙；13px 的小字和 3D 上的大數字密度差了一個量級。
3. 3D 有完整的 CRT 著色器，HUD 只有很淡的 CSS 疊層，交界像一刀切開。
4. 7 顆按鈕平面等距排列，和弧形螢幕牆沒有空間對應。
5. 上方的狀態列也是實心色帶，上下一夾，3D 變成嵌在網頁裡的一塊。
6. HUD 按鈕有 hover 回饋，3D 螢幕卻沒有。

### 7.2 設計
- **拿掉上下兩條實心色帶**：狀態列與頻道列改成透明底，只有線、角標與文字。文字底下加 `--page` 色、60% 不透明的窄底襯，確保對比 ≥ 4.5:1。

  - 選中的鍵和 3D 選中的螢幕之間畫一條 1px 的引線，選取關係一眼就看得出來。
- **雙向 hover 連動**：
  - 懸停 HUD 鍵時，3D 對應螢幕出現四角框預覽（淡）；懸停 3D 螢幕時，HUD 對應鍵亮起。
  - 懸停只是預覽，不改變選取，選取規則和 X2 一樣。
  - 3D 端的懸停射線以 rAF 節流，並沿用 `pickChannel`。
- **構圖納入 HUD**：`fitRestCamera` 加入 HUD 高度參數，讓螢幕牆與雷達台不被控制台遮住；1280×720 離開時也不再碰到特寫畫面（解決 X3 r4 設計師裁示②，見 `os-mode-spec.md` §10 X3 備註）。
- **CRT 一致**：控制台與狀態列放進 B 區的暗角範圍，邊緣跟著 3% 弧面淡出。
- **DOM 結構不變**：
  - 仍是真的 `<button>`，`data-os="hud-ch"`、`hud-list`、`aria-current`、roving tabindex 都保留。
  - `scripts/verify/os-common.mjs` 的選擇器不需要改。
  - 新增的視覺元素（引線、弧形底襯）一律 `aria-hidden`，列印時隱藏。

## 8. 裝置與後備

- **全像模式需要**：寬 ≥ 1280、高 ≥ 720、WebGL2、指標裝置為滑鼠（`(pointer: fine)`）。
