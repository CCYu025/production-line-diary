## 0. 目標與範圍

**目標**：在現有網頁介面之外，加一個**可選用（opt-in）的第三種體驗模式**「PLD/OS 1995」。
使用者坐在一間向量線框的 3D 控制室裡，牆上一排 CRT 螢幕各是一個功能；選一台螢幕，鏡頭推進螢幕、轉台雜訊後進入功能；離開時 CRT 關機、鏡頭拉回控制室。

**定位**：給使用者自己與展示用的「炫技模式」。現場日常記錄仍以網頁模式為主。

**範圍內**

- 新的模式入口、3D 控制室（主畫面）、進出轉場、功能畫面的 CRT 外框、合成音效。
- 功能畫面**沿用現有頁面元件**（儀表板、紀錄、新增／編輯、日曆、報表、回收桶、設定），功能、資料、文字完全不變。

**範圍外（明確不做）**

- 手機與平板（寬度 < 1024px 不支援，見 §7）。
- 後端、API、資料格式的任何改動。
- 把功能畫面本身改成 3D（表單、列表在 3D 裡難用，功能畫面一律是 2D 網頁）。
- 網頁模式（標準主題、Cyber 主題）的任何視覺或行為改變。

### 0.1 名詞

| 名詞 | 意思 |
|---|---|
| OS 模式 | 本文件描述的體驗模式。程式代號 `os` |
| 網頁模式 | 現有介面（標準主題或 Cyber 主題） |
| 控制室（Hub） | OS 模式的主畫面：3D 場景＋HUD |
| 頻道（Channel） | 一個功能入口，對應一台 CRT 螢幕，編號 CH-01～CH-07 |
| 工作站（Station） | 進入頻道後的功能畫面：現有頁面元件＋CRT 外框 |
| 轉場（Transition） | 控制室與工作站之間的進出動畫 |
| 導演（Director） | 管理「開機→控制室→進入→工作站→離開」狀態的狀態機 |
| HUD | 疊在 3D 場景上的 2D 網頁層，包含頻道清單等**真實可操作**的元素 |

## 2. 不可破壞的紅線

1. **網頁模式零差異**：標準主題與 Cyber 主題的畫面、行為、測試結果與 OS 模式導入前完全相同（驗收 S1）。
2. **功能零差異**：工作站裡的每個功能，資料、驗證、文字、流程都和網頁模式相同；OS 模式只包外框與轉場，不改頁面元件的邏輯。
3. **轉場絕不擋住操作**（P3 FX-02 的教訓）：
   - 轉場進行中，任何按鍵或點擊都**立刻跳到轉場終點**，不會被吞掉。
   - 工作站一出現就能操作，第一次點擊就要命中目標。
   - **禁止用 View Transitions 做進出轉場**（VT 期間真實 DOM 不可 hit-test）。轉場一律畫在「不接收點擊」的疊層上（§3.4）。
4. **不繞過既有的離開確認**：表單有未儲存變更時，離開工作站必須先經過現有 `useBlocker` 的確認對話框；使用者取消就不播離開轉場。
5. **列印與報表不變**：OS 模式下列印，畫面必須和標準淺色主題列印完全相同；3D、HUD、CRT 外框、疊層一律不印。
6. **沿用 `docs/cyber-theme-spec.md` §2 全部紅線**（對比、嚴重度色與狀態形狀、焦點、字型自行託管、toast 走 `lib/feedback.ts`、不寫死色碼）。3D 場景的線條顏色從 Cyber token 讀取，不另寫色碼。
7. **無障礙**：3D 場景只是裝飾，所有操作都能透過 HUD 的真實按鈕與鍵盤完成；螢幕閱讀器讀得到每個頻道的名稱與即時訊號（§6）。
8. **`prefers-reduced-motion: reduce` 一律生效**：不播鏡頭移動與轉場動畫，改成直接切換（§5.5）。
9. **相依套件鎖定精確版本**，新增套件只限 §3.6 列出的；要加其他套件先問設計師。
10. **資料安全**：同 `refactor-plan.md` §5，真實資料夾禁止讀寫、禁止當 `DATA_DIR`；開發與驗證一律用複製的範例資料、非 3000 的 port、`NO_OPEN_BROWSER=1`。

## 3. 架構

### 3.1 三層分離

```
┌ 控制室（Hub） ─────────┐   ┌ 轉場（Transition） ┐   ┌ 工作站（Station） ─┐
│ 3D 場景（可替換外觀）  │ → │ 疊層動畫，可跳過   │ → │ 現有頁面＋CRT 外框 │
│ HUD（真實按鈕）        │ ← │                    │ ← │                    │
└────────────────────────┘   └────────────────────┘   └────────────────────┘
                 導演（Director 狀態機）統一管理三層
```

- 三層之間**只透過導演溝通**，彼此不直接呼叫。
- 之後要換主畫面（例如網路空間、低多邊形地球）時，只換控制室這一層。

### 3.2 模式啟用與路由

- 路由用現有的 `createHashRouter`，新增一棵子樹 `/os`：
  - `/os`：控制室。
  - `/os/ch/:channel/*`：工作站。`*` 對應網頁模式的原路由，例如 `/os/ch/02/records`，編輯是 `/os/ch/02/records/63/edit`。
- `/os` 子樹**整棵延遲載入**（`React.lazy`），網頁模式不下載任何 3D 程式碼。
- 模式狀態：`web/src/lib/mode.ts`，`getModePreference()`／`setModePreference()`，key `pld.mode`，每次讀寫都包 try/catch，失敗回傳 `web`。
- 網頁模式的 `/` 依偏好導向 `/dashboard` 或 `/os`。
- **瀏覽器上一頁**：工作站按上一頁＝離開工作站，播離開轉場回控制室；下一頁＝重新進入。轉場跟著路由走，路由是唯一真相。

### 3.3 導演狀態機

| 狀態 | 意思 | 允許的輸入 |
|---|---|---|
| `BOOT` | 開機序列 | 任意鍵：跳過開機（第一次按鍵也啟用音效） |
| `HUB` | 控制室待機 | 選頻道、進入、指令列、離開 OS 模式 |
| `ENTERING(ch)` | 進入轉場 | 任意鍵或點擊：立刻跳到 `STATION` |
| `STATION(ch)` | 工作站 | 頁面本身的一切操作；Esc 或上一頁：離開 |
| `EXITING(ch)` | 離開轉場 | 任意鍵或點擊：立刻跳到 `HUB` |

- 狀態機是純函式（`reducer`），放在 `web/src/features/os/director/`，**必須有完整單元測試**，涵蓋每個狀態的每種輸入。
- `ENTERING` 到一半時，工作站的路由已經切換、頁面已經開始載入資料；轉場只是視覺，不延後任何 API 呼叫。
- `STATION` 時控制室的 3D 繪製迴圈**完全停止**（不是只隱藏），省 GPU。

### 3.4 疊層（轉場的繪製方式）

- 進出轉場畫在一個全螢幕 `<canvas>` 疊層上：`pointer-events: none`、`aria-hidden="true"`。
- **不擷取網頁畫面**：進入時，鏡頭推進的那台螢幕上顯示的是「頻道台標卡」（例如 `CH-02 RECORDS`），不是網頁內容。台標卡填滿畫面的瞬間，在雜訊遮蔽下換成真實工作站。離開時反過來。
- 轉場的「跳過」只是把疊層動畫直接設到終點，不影響下面網頁的狀態。

### 3.5 檔案結構

| 位置 | 內容 |
|---|---|
| `web/src/lib/mode.ts`（新） | 模式偏好讀寫 |
| `web/src/features/os/`（新） | OS 模式全部程式碼，整個資料夾延遲載入 |
| `features/os/director/` | 狀態機、路由同步、按鍵對應 |
| `features/os/hub/` | 3D 場景（控制室、螢幕牆、雷達台、鏡頭） |
| `features/os/hud/` | HUD：頻道清單、指令列、狀態列、EXIT 按鈕 |
| `features/os/transition/` | 疊層 canvas、進出轉場的動畫 |
| `features/os/station/` | CRT 外框、頻道台標、工作站內的返回按鈕 |
| `features/os/audio/` | Web Audio 合成器與音效表 |
| `features/os/os.css`（新） | OS 模式專用樣式，每條規則以 `:root[data-mode="os"]` 開頭；檔尾 `@media print` 全部隱藏 |
| `web/src/app/routes.tsx` | 加 `/os` 子樹與 `/` 的模式導向（唯一要改的既有檔案之一） |
| `web/src/app/Sidebar.tsx` | 加「OS 模式」按鈕（D1） |

既有頁面元件**不得**為了 OS 模式加分支判斷。需要的話，以「外框包住頁面」的方式處理；真的必須改頁面元件時，先問設計師。

### 3.6 相依套件

| 套件 | 用途 | 條件 |
|---|---|---|
| `three` | 3D 繪製 | 鎖精確版本；只在 `/os` 延遲載入的程式碼裡 import |
| `@react-three/fiber` | 以 React 寫 3D 場景 | 同上 |

- **不加** `@react-three/drei`、後處理套件、音效套件、字型或任何 3D 模型檔。
- 線框模型用程式產生（`BufferGeometry`／`EdgesGeometry`），不載入外部檔案。

## 4. 視覺語言

### 4.1 向量線框規則

- **只有線、沒有面**：所有 3D 物件只畫邊線，不畫貼圖、不打光、沒有陰影。
- **色彩取自 Cyber token**：

  | 用途 | token |
  |---|---|
  | 一般線條 | `--line-strong`（遠處淡入 `--line`） |
  | 選中物件、四角框 | `--accent` |
  | 雷達光點 | 嚴重度色（`--good`、`--warning`、`--serious`、`--critical`），和列表左側色條一致 |
  | 背景與霧 | `--page` |

  3D 場景在初始化時以 `getComputedStyle` 讀 token，**不寫死色碼**。
- **景深**：遠處線條以線性霧淡入背景色，避免畫面雜亂。
- **線條數量上限**：整個控制室場景線段總數 ≤ 4,000（驗收 P1 的效能前提）。

### 4.2 年代感處理

| 效果 | 做法 | 預設 |
|---|---|---|
| 低解析度 | 3D 以內部解析度 960×540 繪製，再以 `image-rendering: pixelated` 放大 | 開 |
| 磷光殘影 | 前一幀以 85% 不透明度疊回（自製回饋緩衝，不用後處理套件） | 開；效能不足時自動關（§9.4） |
| 掃描線 | 沿用 Cyber 主題的 `body::after` 掃描線 | 開 |
| 輕微晃動 | 控制室鏡頭以極小幅度呼吸式晃動（±0.3°，週期 8 秒） | 開；減少動態效果時關 |

### 4.3 控制室場景

- **地板**：透視網格，延伸到霧中。
- **螢幕牆**：7 台 CRT 以弧形排列在鏡頭前方，每台是一個線框外殼加一個螢幕面。
- **螢幕面的內容**：用 2D Canvas 畫成貼圖，內容是頻道代號、名稱、一個即時訊號（§4.4）。這是唯一允許的「貼圖」，因為它本身就是一塊會發光的螢幕。
- **選中提示**：被選中的螢幕外框變主青色，外圍加四角框（分鏡第 1 格）。
- **雷達台**：螢幕牆前方地面上的圓形線框台，掃描線旋轉；每台機台是一個光點（§4.4）。
- **待機巡視**：60 秒無操作時，鏡頭緩慢巡視整間控制室；任何輸入立刻回到原位。

### 4.4 即時訊號（主畫面要有用）

全部用**現有 API**（`getMeta`、`listRecords`、`getAggregate`）與現有的 TanStack Query 快取，不新增後端端點。

| 頻道 | 螢幕上的訊號 |
|---|---|
| CH-01 儀表板 | 待處理件數 |
| CH-02 紀錄 | 今日新增筆數 |
| CH-03 新增 | 閃爍的 `READY▮` |
| CH-04 日曆 | 今天日期與當日筆數 |
| CH-05 報表 | 本月筆數 |
| CH-06 回收桶 | 回收桶筆數 |
| CH-07 設定 | 機台數 |

- **雷達光點**：近 7 天有紀錄的機台各一個點，顏色取該機台最嚴重的未解決紀錄；有新紀錄時光點脈衝一次並發出提示音。
- 光點的角度依機台名稱的雜湊固定，每次開啟位置相同。

### 4.5 HUD

HUD 是疊在 3D 場景上的一般網頁層，是 OS 模式的**真實操作介面**，3D 場景只是它的視覺化。

- **頻道清單**（畫面底部）：7 個真實的 `<button>`，文字例如 `CH-02 紀錄 · 今日 3`。方向鍵移動、Enter 進入；和 3D 螢幕的選中狀態雙向同步。
- **狀態列**（畫面頂部）：`PLD/OS 1995`、時間、音效狀態、`EXIT TO WEB` 按鈕。
- **指令列**：按 `/` 開啟，可輸入 `dash`、`rec`、`new`、`cal`、`rep`、`trash`、`set`、`rec 63`（直接開某筆紀錄）、`exit`、`help`；輸入有自動完成。
- 字型、色彩、焦點環全部沿用 Cyber 主題。

### 4.6 工作站

- 頁面元件外面包一個 **CRT 外框**：圓角螢幕邊框、四角輕微暗角、右上角頻道台標（例如 `CH-02`）。
- 外框內就是現有的 Cyber 主題頁面，捲動、對話框、面板都在外框內正常運作。
- 外框左上角有一個真實的「◀ HUB」按鈕，等同 Esc。
- 網頁模式的側欄**不顯示**；頁面之間的切換一律回控制室或用指令列。

## 5. 轉場與動畫

### 5.1 共通規則

1. **任何轉場都可跳過**：轉場期間第一次按鍵或點擊＝跳到終點；這次輸入本身**不會**傳給下面的頁面（避免誤觸），之後的輸入正常。
2. **轉場不延後任何事**：路由切換、API 呼叫、焦點移動都在轉場一開始就發生；轉場只是視覺。
3. **只用疊層 canvas 與 3D 鏡頭**做轉場，不用 View Transitions、不對網頁元素做 `clip-path` 進場動畫。
4. 所有時間定義成 token，放在 `features/os/transition/timing.ts`，測試會檢查總長上限。
5. 3D 與疊層動畫只能在 `requestAnimationFrame` 裡更新，不得造成網頁版面重排（CLS = 0）。

### 5.2 進入轉場（控制室 → 工作站）

| 段落 | 時間 | 畫面 | 聲音 |
|---|---|---|---|
| E1 鏡頭推進 | 0–600ms | 鏡頭朝選中的螢幕推進，其他螢幕滑出畫面 | 推進時的低頻上升音 |
| E2 台標卡 | 600–750ms | 螢幕面填滿畫面，顯示 `CH-02 RECORDS`、`signal lock ▮▮▮▯` | 繼電器喀噠一聲 |
| E3 轉台雜訊 | 750–1000ms | 疊層出現雜訊、水平撕裂、垂直滾動；雜訊遮蔽下 3D 隱藏、工作站現身 | 轉台雜訊聲 |
| E4 訊號鎖定 | 1000–1200ms | 雜訊淡出，工作站完整顯示，台標縮到右上角 | — |

總長 ≤ 1,200ms。焦點在工作站現身時移到頁面主內容（沿用現有換頁的焦點規則）。

### 5.3 離開轉場（工作站 → 控制室）

| 段落 | 時間 | 畫面 | 聲音 |
|---|---|---|---|
| X1 垂直收合 | 0–150ms | 工作站畫面（疊層模擬）垂直壓扁成一條亮線 | CRT 關機的高頻「啾」 |
| X2 收成亮點 | 150–300ms | 亮線水平收成一個亮點 | — |
| X3 亮點殘留 | 300–400ms | 亮點淡出 | — |
| X4 鏡頭拉回 | 300–900ms（與 X3 重疊） | 從那台螢幕拉回控制室原位 | 低頻下降音 |

- 總長 ≤ 900ms。
- 焦點回到對應頻道的 HUD 按鈕。
- X1 的「工作站畫面」用簡化的亮面塊模擬，**不擷取網頁**。

### 5.4 快速通道

- **數字鍵 1–7**：在控制室直接進入對應頻道（不必先選）。
- **`N` 鍵**：在任何地方（控制室或工作站）直接開「新增紀錄」，用**短轉場**：只有 E3＋E4，總長 ≤ 300ms。
- 在工作站時，指令列切換頻道一律用短轉場。
- 這些全域按鍵在焦點位於輸入框、文字區、可編輯內容、或有對話框／彈出選單開著時**一律不作用**。

### 5.5 開機序列

| 段落 | 內容 |
|---|---|
| B1 | 黑畫面，`PRESS ANY KEY`（點擊也可） |
| B2 | BIOS 自檢文字逐行出現：記憶體、`PLD/OS 1995`、機台數、紀錄數（真實數字） |
| B3 | CRT 亮起（一條亮線展開成全畫面） |
| B4 | 控制室線框從中心向外描繪出現 |

- 完整版 ≤ 4 秒，每個分頁工作階段只播一次（D3）；之後是只有 B3＋B4 的短開機，≤ 1 秒。
- 任意鍵跳過。
- **B1 的第一次按鍵用來啟用音效**（瀏覽器要求互動後才能出聲）。

### 5.6 減少動態效果

開啟 `prefers-reduced-motion: reduce` 時：

- 不播開機 B2–B4，直接顯示控制室（B1 保留，用來啟用音效）。
- 進出轉場改成**直接切換**，不播任何疊層動畫與鏡頭移動。
- 控制室鏡頭固定、不巡視、不晃動；雷達掃描線停止，光點不脈衝。
- 音效照常（音效與動態效果無關）。

## 6. 無障礙

1. **完全可用鍵盤操作**：控制室透過 HUD 按鈕，工作站沿用現有頁面的鍵盤操作。
2. **3D 畫布**是 `aria-hidden="true"`，所有資訊都在 HUD 的文字裡。
3. **頻道按鈕的可及名稱**包含訊號，例如「CH-02 紀錄，今日 3 筆」。
4. **焦點**：進入工作站時，焦點移到頁面主內容；離開時，焦點回到該頻道按鈕。
5. **狀態宣告**：轉場開始與完成，用一個 `aria-live="polite"` 區域宣告「進入紀錄」／「回到控制室」。
6. **開機文字**是裝飾（`aria-hidden`），另有一句螢幕閱讀器可讀的「PLD/OS 載入中」。
7. **對比**：HUD 文字對比 ≥ 4.5:1（沿用 Cyber 色票，測試同樣檢查）。

## 7. 裝置與後備

| 情況 | 行為 |
|---|---|
| 視窗寬度 < 1024px 或高度 < 600px | 顯示終端機風格訊息「PLD/OS 需要桌面終端機（≥1024×600）」，附「改用網頁模式」按鈕；視窗放大後自動進入 |
| 瀏覽器不支援 WebGL，或 WebGL 初始化失敗 | 顯示「顯示卡不支援，已改用網頁模式」，自動切回網頁模式的 Cyber 主題；不記住為 `os` |
| 執行中 WebGL context 遺失 | 嘗試恢復一次；失敗就同上 |
| 觸控裝置 | 不特別處理（U1）；寬度條件已排除大部分手機 |

## 8. 音效

- **全部用 Web Audio 即時合成**：振盪器＋雜訊緩衝＋包絡，不使用任何音檔。
- 音效表放在 `features/os/audio/sounds.ts`，每個音效是一個參數物件，有單元測試檢查參數範圍。

| 事件 | 聲音 | 長度 |
|---|---|---|
| 開機 B2 | 撥接連線音（雙音頻＋雜訊）、BIOS 嗶一聲 | ≤ 2.5s |
| 控制室待機 | CRT 低頻嗡聲，非常小聲，持續 | 持續 |
| 選頻道（左右移動） | 繼電器喀噠 | ≤ 60ms |
| 進入 E1／E3 | 上升音、轉台雜訊 | 對應段落 |
| 離開 X1／X4 | 高頻「啾」、下降音 | 對應段落 |
| 雷達新異常 | 短促雙音提示 | ≤ 200ms |
| 指令錯誤 | 低音嗶 | ≤ 150ms |

- **主音量上限**：-18 dBFS，所有音效經過同一個總音量節點。
- **靜音**：`M` 鍵或狀態列按鈕；偏好存在 `pld.os.sound`（`on`／`off`），預設 `on`。
- `AudioContext` 建立失敗時一律靜默，不影響任何功能。
- 分頁切到背景時暫停待機嗡聲。

## 9. 驗收條件

每期只驗收該期涵蓋的項目（見 §10）。

### 9.1 自動化（CI 五個指令都要綠燈）

| 編號 | 條件 |
|---|---|
| A1 | 導演狀態機：每個狀態 × 每種輸入的轉移都有測試，包含「轉場中輸入＝跳到終點」 |
| A2 | `lib/mode.ts`：讀寫失敗回傳 `web`；`?mode=os` 覆寫並寫回 |
| A3 | `os.css` 每條規則以 `:root[data-mode="os"]` 開頭；`@media print` 隱藏所有 OS 元素 |
| A4 | 轉場時間 token：進入 ≤ 1,200ms、離開 ≤ 900ms、短轉場 ≤ 300ms、完整開機 ≤ 4s |
| A5 | 網頁模式的程式進入點不 import `three`、`@react-three/fiber`、`features/os/`（以 build 產物分析檢查） |
| A6 | 全域按鍵在輸入框、可編輯內容、對話框開啟時不作用 |
| A7 | 音效參數範圍與總音量上限 |

### 9.2 操作不被擋（最重要）

| 編號 | 條件 |
|---|---|
| I1 | 進入與離開轉場的每個時間點各點擊一次：該次點擊讓轉場跳到終點，且下一次點擊命中目標（真實瀏覽器實測，1× 與 4× CPU 降速） |
| I2 | 工作站現身後 50ms 內的第一次點擊命中目標 |
| I3 | 疊層 canvas 在所有狀態下 `pointer-events: none`；任何時刻 `document.elementFromPoint` 不會落在疊層上 |
| I4 | 連續快速操作（進入→Esc→進入，間隔 100ms，重複 10 次）：最後狀態與路由一致，沒有殘留疊層，焦點位置正確 |

### 9.3 功能一致

| 編號 | 條件 |
|---|---|
| E1 | 在工作站完成：新增紀錄（含照片）、編輯、刪除與還原、永久刪除、匯出 Excel、報表列印、設定儲存；結果與網頁模式相同 |
| E2 | 表單有未儲存變更時，Esc、◀ HUB、上一頁、指令列切換都先出現確認；取消後留在原處、不播轉場 |
| E3 | 上一頁＝離開、下一頁＝進入；直接開 `/os/ch/02/records/63/edit` 能進入該工作站 |
| E4 | OS 模式下列印與標準淺色主題列印相同（截圖雜湊、PDF 頁數） |

### 9.4 效能

在**使用者的電腦**上量測（主要使用裝置），1920×1080。

| 編號 | 條件 |
|---|---|
| P1 | 控制室待機與選頻道：中位數 ≥ 55fps；4× CPU 降速 ≥ 30fps。不達標時依序關閉：磷光殘影 → 降內部解析度到 640×360 → 待機巡視 |
| P2 | 工作站狀態下，3D 繪製迴圈的 `requestAnimationFrame` 呼叫為 0 |
| P3 | 工作站內的頁面操作效能與網頁模式 Cyber 主題相差 ≤ 5% |
| P4 | 網頁模式主程式 gzip 增加 ≤ 2KB；OS 延遲載入的程式 gzip ≤ 300KB |
| P5 | 從點「OS 模式」到控制室可操作（跳過開機） ≤ 1.5 秒 |
| P6 | 進出工作站 20 次後，JS heap 增加 ≤ 10%，WebGL 資源有正確釋放 |

### 9.5 安全與零差異

| 編號 | 條件 |
|---|---|
| S1 | 網頁模式標準主題（淺／深）與 Cyber 主題：逐元素樣式比對（沿用 Cyber P1–P4 的 C1 腳本）零差異 |
| S2 | 網頁模式所有既有測試不改動即通過 |
| S3 | 開發與驗證全程未讀寫真實資料夾 |

### 9.6 設計審查

- 每期提供：控制室靜態截圖、每段轉場的影格條、工作站在 1280／1920 寬的截圖。
- 設計師對照本文件判定「符合／不符合」，列出要改的地方。

### 9.7 手動情境（使用者實測）

1. 在自己電腦上開啟 OS 模式，完整看一次開機、進入每個頻道、離開。
2. 用 OS 模式新增一筆真實格式的紀錄（用範例資料副本），確認流程順手。
3. 確認音效音量合適、靜音有效。
4. 展示情境：讓控制室待機 2 分鐘，確認巡視與雷達效果。

## 11. 風險與回退

| 風險 | 對策 |
|---|---|
| 使用者電腦的顯示卡跑不動 | 低解析度繪製＋線段上限；P1 的降級順序；X0 先在使用者電腦上量測 |
| 轉場擋點擊（重蹈 FX-02） | 紅線 3；疊層 `pointer-events: none`；I1–I4 每期都驗 |
| 3D 套件讓網頁模式變慢 | `/os` 整棵延遲載入；A5、P4 檢查 |
| 工作站裡的頁面因外框而版面錯亂 | 外框只加邊距與裝飾，不改頁面內部；S1 與設計審查 |
| 新增功能時忘了加頻道 | 頻道表集中在一個設定檔，測試檢查每個頻道都對應到存在的路由 |
| 完全放棄這個實驗 | 刪除 `features/os/`、`lib/mode.ts`、`os.css`、`/os` 路由、側欄按鈕與兩個套件；網頁模式不受影響 |

## 12. 執行流程與角色

比照 `docs/cyber-theme-spec.md` §12：

| 角色 | 負責 | 執行者 |
|---|---|---|
| 主視覺設計師／顧問 | 這份規格書、每期的設計簡報、設計審查、回答設計疑問、裁定偏離 | 主模型 |
| 工作協調 | 依本文件派發每期工作、串起實作／驗證／修正／文件檢查、開 PR、回報 | Sonnet |
| 實作、驗證、修正、文件檢查 | 同 `refactor-plan.md` §5；驗證依 `.claude/agents/verifier.md` | Sonnet |

**每一期的流程**

1. 設計師寫該期的設計簡報（補充本文件沒寫到的細節），使用者確認後開始。
2. 協調者派發實作：在自己的 git worktree，從最新 `origin/main` 開分支。
3. CI 綠燈後，**獨立驗證者**（不是實作者）依 §9 中該期的驗收條件實測，並提供設計審查用的截圖與影格條。
4. 有問題就修正，再由**新的**驗證者重驗。
5. 設計審查：不符合就退回第 4 步。實作中遇到本文件沒寫到、或寫了但做不到的地方，**先問設計師，不要自行決定**。
6. 文件檢查（`CLAUDE.md`／`AGENTS.md` 同步、`README.md`），並在 §10 標註狀態與 PR。
7. **合併要使用者明確同意**（每個 PR 各自同意）；合併後才開始下一期。
